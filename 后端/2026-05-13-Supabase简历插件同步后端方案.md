# Beyond CV 后端方案：简历内容与插件资料绑定

日期：2026-05-13

## 目标

把 Beyond CV 页面里创建、识别、编辑后的简历内容，和 Chrome 插件里的本地填表资料绑定到同一份后端数据。

最终用户效果：

1. 用户在 Beyond CV 页面制作或修改简历。
2. 点击「同步当前简历」。
3. 页面把结构化简历和插件可用的 profile 写入 Supabase。
4. 系统返回一个同步码。
5. 插件输入或保存这个同步码后，可拉取最新 profile。
6. 插件在字节、官网招聘系统等页面使用同一份资料直填。

## 大师视角实现路径

不要让插件和网页各自维护一份孤立数据。更稳的路径是建立一个中间数据层：

- 页面负责生产完整简历模型。
- 后端负责保存版本化的简历与插件 profile。
- 插件只消费后端 profile，不再依赖页面当前是否打开。
- 普通扫描/直填仍然在插件端执行，后端不接触第三方招聘页面。

这样以后可以继续扩展：

- 多份简历版本。
- 针对不同岗位生成不同 profile。
- 插件拉取岗位定制字段。
- 用户登录和多设备同步。

## 数据表

表名：

```sql
public.bcv_profile_syncs
```

用途：

保存 Beyond CV 页面生成的简历结构和插件可用的填表 profile。

字段：

```sql
sync_id uuid primary key default gen_random_uuid()
user_id uuid references auth.users(id) on delete cascade
sync_secret_hash text not null
resume_payload jsonb not null default '{}'::jsonb
plugin_profile jsonb not null default '{}'::jsonb
source text not null default 'prototype'
created_at timestamptz not null default now()
updated_at timestamptz not null default now()
```

索引：

```sql
bcv_profile_syncs_updated_at_idx on updated_at desc
bcv_profile_syncs_user_id_key unique on user_id where user_id is not null
bcv_profile_syncs_user_updated_idx on user_id, updated_at desc
```

触发器：

```sql
bcv_profile_syncs_set_updated_at
```

作用：

每次更新数据时自动刷新 `updated_at`。

## 权限设计

已开启 RLS：

```sql
alter table public.bcv_profile_syncs enable row level security;
```

当前不开放浏览器直接访问表。

读写都通过 Edge Function 代理完成。这样可以避免静态页面拿 publishable key 后直接枚举或修改整张表。

账户模式下，Edge Function 会读取请求里的 Supabase Auth JWT，解析出 `user_id`，然后只读写该账户自己的同步记录。

## Edge Function

函数名：

```text
bcv-profile-sync
```

访问地址：

```text
https://fsdashpviavdlxyicibr.supabase.co/functions/v1/bcv-profile-sync
```

JWT 校验：

```text
verify_jwt = false
```

说明：函数内部仍会读取并校验 Supabase Auth access token。关闭 Supabase 网关层 JWT 校验，是为了让浏览器从 `file://` 或外部分发网址发起的 CORS `OPTIONS` 预检请求能正常通过，避免前端出现 `Failed to fetch`。

当前支持两个 action。

### upsert

页面保存或更新简历时调用。

请求体：

```json
{
  "action": "upsert",
  "token": "可选，已有同步码时传入",
  "resume": {},
  "profile": {},
  "source": "beyond-cv-prototype"
}
```

行为：

- 如果用户已登录，按 `user_id` 保存或更新该账户的资料。
- 如果用户未登录且没有 token，后端生成新的 `sync_id` 和 `sync_secret`。
- 如果用户未登录但传入 token，校验 secret hash 后更新该 token 对应资料。
- 写入 `resume_payload` 和 `plugin_profile`。
- 返回完整同步码。

返回：

```json
{
  "token": "sync_id.sync_secret",
  "syncId": "uuid",
  "resume": {},
  "profile": {},
  "updatedAt": "timestamp"
}
```

### get

插件同步资料时调用。

请求体：

```json
{
  "action": "get",
  "token": "sync_id.sync_secret"
}
```

行为：

- 如果用户已登录，按 `user_id` 返回该账户最新 resume 和 profile。
- 如果用户未登录，使用 token 里的 secret 计算 SHA-256。
- 与数据库里的 `sync_secret_hash` 比对。
- 校验成功后返回 resume 和 profile。

返回：

```json
{
  "token": "sync_id.sync_secret",
  "syncId": "uuid",
  "resume": {},
  "profile": {},
  "updatedAt": "timestamp"
}
```

## 同步码机制

同步码格式：

```text
sync_id.sync_secret
```

设计原因：

- `sync_id` 用于定位记录。
- `sync_secret` 只在用户本地和插件中保存。
- 数据库只保存 `sync_secret_hash`，不保存明文 secret。
- 即使表数据泄漏，也不能直接拿到可用同步码。

这不是最终生产级账号体系，但比纯本地 demo 和裸表读写稳很多。

- 创建账户。
- 登录。
- 退出。

登录后同步简历时，页面会使用账户 access token 调用 Edge Function。后端按 `user_id` 保存资料。

插件弹窗新增：

- 账户邮箱。
- 密码。
- 登录账户。
- 退出。
- 从云端同步资料。

插件登录后会用同一账户 access token 调用 Edge Function 的 `get` action，把后端 `plugin_profile` 写入 `chrome.storage.sync.profile`。

## 2026-05-13 追加：取消邮箱确认，支持外部网址 Demo

用户反馈确认邮件跳转 `localhost` 时会被拒绝。原因是 Supabase Auth 默认邮件确认会跳转到项目 Site URL，而本地没有服务监听该地址；如果以后把 demo 发给别人通过网址打开，依赖 `localhost` 更不稳定。

已调整为 demo 友好方案：

- 取消前端 `/signup` 邮件确认流程。
- Edge Function 新增 `demo_signup` action。
- `demo_signup` 使用 Supabase Admin API 创建用户，并设置 `email_confirm: true`。
- 创建成功后立刻用邮箱密码登录，返回 Supabase access token。
- 页面保存 access token 到本地 session。
- 用户创建账号后无需打开确认邮件，可直接保存简历。
- 之后可把 demo 账号邮箱和密码发给测试者，测试者在自己电脑打开网址后直接登录。

接口：

```json
{
  "action": "demo_signup",
  "email": "tester@example.com",
  "password": "Demo123456"
}
```

返回：

```json
{
  "mode": "account",
  "created": true,
  "access_token": "...",
  "refresh_token": "...",
  "user": {}
}
```

验证：

- `demo_signup` 创建已确认用户：通过。
- 使用返回的 access token 保存 `resume_payload` 和 `plugin_profile`：通过。
- 保存模式返回 `account`：通过。

说明：

- 这适合 demo 分发和测试。
- 正式生产环境仍建议恢复邮箱确认或接入更完整的邀请/组织权限机制。
- 不建议系统自动邮件发送明文密码；demo 阶段由产品方手动把测试账号和密码发给测试者更稳。

## 安全边界

当前后端只负责 Beyond CV 自己的数据同步，不自动访问招聘网站，也不自动提交申请。

插件在第三方招聘页面上的行为仍然是：

- 用户主动点击。
- 只填字段。
- 不保存第三方页面账号密码。
- 不自动提交申请。

证件号、身份证、隐私协议、薪资等敏感字段仍不默认批量填入。
