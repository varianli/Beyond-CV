# Beyond CV 更改意见记录：页面字段模型直填

日期：2026-05-12

## 问题

用户反馈：
- 字节招聘页面仍然显示「未匹配」。
- 只靠扫描匹配字段不稳定。
- 更合理的方式应该是先把网页转换成代码可以理解的形式，再把内容插入合适的位置。

## 处理思路

从「字段匹配列表」升级为两步：

1. 页面字段模型化
   - 扫描当前页面可见输入控件。
   - 读取控件位置、当前值、类型。
   - 建立页面可见短文本索引。
   - 将输入框和附近的可见标签组合成字段模型。

2. 代码直填
   - 不依赖 popup 中的匹配列表。
   - 按可见字段名和屏幕位置找最近输入框。
   - 用 React/Vue 兼容的 setter 写入值，并触发 `input` / `change` 事件。

## 已新增能力

- 新增 `BCV_PAGE_MODEL`：
  - 将当前网页转换成代码可理解的字段模型。
- 新增 `BCV_DIRECT_FILL`：
  - 根据字段模型直接填入页面字段。
- popup 新增按钮：
  - 「按页面字段直填」

## 直填字段范围

当前直填优先覆盖：

- 姓名
- 手机号码
- 邮箱
- 期望工作地点
- 教育起始时间
- 教育结束时间
- 学历类型
- 学校名称
- 学历
- 学院
- 专业
- 学位
- 实验室
- 研究方向
- 导师

其中证件号等敏感字段暂不默认直填。

## 技术细节

- 新增 `DIRECT_TARGETS` 字段映射表。
- 新增 `fieldsNearLabel()`：
  - 根据可见 label 的屏幕位置寻找最近输入框。
- 新增 DOM-first 字段模型：
  - 读取 `label[for]`、`aria-labelledby`、`aria-label`、placeholder、name/id。
  - 读取 form item 父容器、label/title 类节点、前置兄弟节点。
  - DOM 模型优先，屏幕就近关系只做兜底。
- 新增 `directFill()`：
  - 逐项按字段名和资料库写入。
- content script 版本升级到 `0.1.5`。
- popup 直填改为通过 `chrome.scripting.executeScript` 注入主页面环境执行，减少 React 受控输入和 content script 隔离造成的失败。
- manifest 版本升级到 `0.1.6`。

## 追加修正

用户追问不同布局下是否只是就近或横向扫描。已确认并调整为：

- DOM 语义优先：读取 `label[for]`、`aria-labelledby`、`aria-label`、placeholder、name/id、表单项容器和字段标题。
- 视觉位置兜底：只有 DOM 语义不足时，才使用同一行或上方 label 与输入框的位置关系。
- 文本字段与选择字段分流：姓名、手机号、邮箱等文本字段优先写入 `input` / `textarea`，不再把 `+86` 国家区号下拉框当作手机号候选。
- 表单项边界收紧：字段模型向上读取 DOM 时停在当前字段容器内，避免把上一个表单项的文字污染到下一个输入框。
