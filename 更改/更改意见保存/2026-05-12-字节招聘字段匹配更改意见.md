# Beyond CV 更改意见记录：字节招聘字段匹配

日期：2026-05-12

## 问题

页面：`https://jobs.bytedance.com/campus/resume/edit`

现象：
- 插件已经可以注入页面并框出输入区。
- popup 显示 `0 可填 / 0 已识别 / 40 字段`。
- 页面上的「姓名、邮箱、学校名称、起止时间」等字段仍显示「未匹配」。

## 原因判断

- 字节招聘页面的表单 label 和 input 并不是标准 `label[for]` 绑定，也不一定在同一个最近容器里。
- 旧逻辑主要从 `aria-label`、`placeholder`、`name/id`、最近 form item 文本里取字段名，因此能扫到输入框，但拿不到视觉上显示的「姓名、邮箱、学校名称」。
- 某些控件会把整段表单文字抓进来，其中包含「个人证件」等敏感词，导致 popup 出现一个很长的「需手动确认」块，污染匹配结果。
- 「学历类型」和「学历」被混用：字节里的「学历类型」是统招全日制/非全日制，「学历」才是硕士/本科。
- 旧 content script 有简单的 `__beyondCvContentLoaded` 注入标记，扩展重新加载后新脚本可能被旧标记挡住。

## 处理

- 扫描前建立当前页面的可见短文本索引。
- 对每个输入框按屏幕坐标查找：
  - 同一行左侧最近 label。
  - 输入框上方最近 label。
  - 上方左对齐 label。
- `fieldText()` 现在优先使用视觉邻近 label，再补充 `aria-label / label[for] / aria-labelledby / placeholder / name / id`。
- 复选框、单选框、文件上传控件从自动扫描字段中排除。
- 字段分类改为 `classifyField(el, labelText)`，可以结合元素位置判断。
- 对「起止时间」做左右输入框判断：
  - 左侧输入框映射教育起始时间。
  - 右侧输入框映射教育结束时间。
- 「学历类型」与「学历」拆开：
  - `educationType = 统招全日制`
  - `educationLevel = 硕士`
  - `degree = 金融硕士`
- 新增「期望工作地点 / 工作地点 / 地点」到城市类字段。
- content script 注入标记改为版本化：
  - `__beyondCvContentVersion = 0.1.4`
  - 防止旧脚本挡住新脚本。

## 验证

- `node --check beyond-cv-extension/content.js`：通过
- `node --check beyond-cv-extension/popup.js`：通过
- `node --check beyond-cv-extension/options.js`：通过
- `node --check beyond-cv-extension/background.js`：通过
- `beyond-cv-extension.zip`：已重新生成

## 使用注意

需要在 `chrome://extensions` 中点击 Beyond CV 的「重新加载」，然后刷新字节招聘页面，再重新扫描。

如果页面仍旧显示 0 匹配，优先检查是否仍在运行旧 content script；刷新招聘页面通常可以清掉旧脚本上下文。
