# Beyond CV 前端单页原型决策记录

## 1. 目标与交付

- 原型名称：Beyond CV 单页 Web 原型。
- PRD 来源：`C:\Users\varianli\OneDrive\Desktop\Beyond CV\PRD`。
- 输出文件：`C:\Users\varianli\OneDrive\Documents\New project\beyond-cv-prototype.html`。
- 交付形态：可直接在浏览器打开的单文件 HTML/CSS/JS Demo。
- 技术依赖：允许使用 Tailwind CDN 与 lucide 图标 CDN；不接后端，不持久化数据。

## 2. 产品定位

- 第一屏定位为登录后的工作台，不做营销官网。
- 主任务为“制作简历”，点击后直接进入简历编辑器，不先强制进入 onboarding。
- 插件安装作为完整引导区呈现，不只做一个按钮入口。
- 原型优先演示核心能力：简历制作、岗位适配摘要、插件安装连接和测试填入。

## 3. 页面结构

- 全局框架：左侧导航 + 顶部状态栏 + 主内容区。
- 简历制作区在主内容中置顶，避免用户进入页面后还要先越过工作台。
- 工作台总览：
  - 保存状态。
  - 插件状态。
  - 最近岗位材料。
  - 核心入口：制作简历、安装插件。
  - 首屏产品说明压缩为一行工具横幅，不做大面积 hero。
  - 不展示首屏资料覆盖率环图，不放重复的“制作中文产品岗简历”任务卡。
- 简历制作区：
  - 默认中文简历，保留 English 切换。
  - 左侧为固定 A4 实时预览，便于用户边填边看。
  - 右侧为可上下滚动的录入表单，按基础信息、教育背景、实习经历、在校活动、技能排序。
  - 右侧顶部提供“大段粘贴识别”，参考模板2的使用方式：用户可以粘贴完整经历文本，再模拟识别到下方字段。
  - 每段教育、实习、活动都有“加入简历”勾选，不限制实习经历为 3 段，由用户自行选择放哪几段。
  - 每个模块提供“添加教育 / 添加实习 / 添加活动”入口。
  - A4 预览需贴近用户提供的模板排布：姓名和联系方式居中，学校/公司信息左侧，城市/日期等信息右侧对齐，section 标题下方有横线。
  - A4 预览右上角保留虚线头像占位框，让用户自行判断是否放头像。
  - 默认预览内容使用模板1的结构翻译成中文占位，用户输入后逐步替换。
  - 不提供手动排版密度滑杆；根据勾选内容自动调整，优先压缩行间距，再压缩字号。
  - 自动排版基于 A4 预览边界检测：渲染后检测 `scrollHeight` 与 `clientHeight`，若溢出先逐步降低行距和段距，达到极限后再逐步降低字号和页边距。
  - 字体和行距参考模板3，中文简历预览使用宋体风格、紧凑行距和专业 CV 的横线分区。
- 岗位适配摘要区：
  - 展示 JD 解析关键词。
  - 展示字段短答、Cover Letter、Behavior Question、适配简历建议。
  - 展示敏感字段开关。
- 插件安装区：
  - 展示插件状态卡。
  - 三步引导：安装插件、连接账号、扫描官网字段。
  - 展示使用边界。
  - 提供模拟表单测试“一键填入”。
- 隐私控制区：
  - 强调私有资料库、敏感字段标记、导出与删除。

## 4. 视觉方向

- 风格关键词：苹果系统工具感、浅色、通透、克制、精密排版、中高信息密度。
- 设计参考倾向：macOS / iPadOS 生产力应用，而不是发布会官网或营销首页。
- 视觉规则：
  - 使用细边框、柔和阴影、玻璃拟态背景和系统级圆角。
  - 避免大 hero 宣传页、夸张渐变、过度装饰。
  - 使用图标按钮、分段控件、开关、滑杆、状态标签和真实 A4 文档画布。
  - 保持工具型页面的信息密度，但不牺牲扫描清晰度。

## 5. 样例数据

- 示例用户：互联网产品方向求职者。
- 默认简历语言：中文。
- 示例内容：
  - 在线教育 App 增长项目。
  - B 端 SaaS 需求调研。
  - 校园产品社群负责人。
  - 产品、数据、语言技能。
- 最近岗位示例：
  - 字节跳动 - 产品经理实习生。
  - 小红书 - 增长产品实习生。
- 插件测试字段：
  - 姓名。
  - 申请动机。

## 6. 交互范围

- 导航锚点滚动。
- 当前导航高亮。
- 简历中文 / 英文切换。
- 编辑姓名、联系方式、教育经历、项目经历、技能后实时更新 A4 预览。
- 点击“AI 理解并填入下方空格”会先对整段文本做模型式语义理解，再把结果映射到基础信息、教育、实习、活动和技能字段。
- 大段粘贴不依赖用户严格使用符号或换行；真实产品应由模型输出结构化 JSON，包括经历类型、机构名称、地点、角色、时间和经历内容，前端只负责把 JSON 填入可编辑卡片。
- 识别到粘贴文本里有新的实习 / 教育 / 活动对象时，系统会自动新增对应卡片并默认勾选加入简历。
- 大段粘贴原文必须保留在输入框中，方便用户对照 AI 理解结果，不能因为解析过程吞掉原文内容。
- 大段粘贴和 JD 粘贴在输入为空时不能走演示 fallback，也不能显示“AI 已理解”；必须提示用户先粘贴内容，且不自动填入任何示例数据。
- 技能、活动与兴趣是可选模块，需要提供“加入简历”勾选；用户不填写或取消勾选时，A4 预览不展示该模块。
- 导出需要提供 Word 与 PDF 两个入口：PDF 使用浏览器打印/另存为 PDF，Word 在原型中导出 Word 可打开的 `.doc` 文件。
- A4 预览区域要尽量放大利用左侧空间，减少预览面板里的无意义空白。
- 简历分区标题字号需要跟随自动排版一起缩放，不能只缩放正文。
- 岗位适配区支持粘贴完整 JD，AI 理解岗位名称、关键词和材料生成方向后，刷新 JD 解析与生成材料卡片。
- 大段识别后必须有明确反馈：按钮 loading / 成功文案、识别结果状态条、下方字段高亮，并滚动到基础信息区域。
- 点击“添加教育 / 添加实习 / 添加活动”会插入一个可编辑占位段落，并同步进入预览。
- 排版密度滑杆影响 A4 预览密度。
- 经历勾选影响“一页适配”状态提示。
- AI 压缩按钮模拟压缩 bullet，并自动切换到紧凑密度。
- 插件连接状态可模拟切换。
- 插件测试表单支持扫描并填入测试字段。
- 敏感字段开关可切换，但不接真实生成逻辑。

## 7. 明确边界

- 不实现真实 Chrome Extension 通信。
- 不实现真实账号、数据库、导出 PDF/DOCX。
- 不实现完整 onboarding 流程。
- 不自动提交申请。
- 不自动同意法律协议或 consent。
- 家庭信息、成绩、证件类字段默认不进入批量填入。

## 8. 验收口径

- 首屏可见“制作简历”和“安装插件”入口。
- 页面整体像登录后的生产工具，而不是宣传页。
- 简历编辑后 A4 预览能同步变化。
- 插件安装区能说明状态、步骤、边界，并能模拟填入。
- 桌面端保持左侧导航和工作台布局。
- 移动端导航收敛，内容纵向排列，不出现明显遮挡或溢出。
