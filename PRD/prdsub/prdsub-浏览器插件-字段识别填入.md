# Beyond CV 页面 PRD：浏览器插件 - 字段识别填入

## 1. 页面概述

| 字段 | 内容 |
|-----|------|
| 页面名称 | 浏览器插件侧栏 |
| 所属模块 | 浏览器插件辅助填写 |
| 页面入口 | Chrome Extension popup / side panel |
| 页面优先级 | P0 |
| 主要用户 | 正在招聘官网填写申请表的求职者 |
| 前置依赖 | 用户已登录插件，当前页面为招聘官网 |
| 后置动作 | 用户单击填入字段，并自行提交官网表单 |

插件侧栏是 Beyond CV 解决“每家公司重复填写半小时”的关键体验。插件不自动提交申请，不绕过官网限制，而是在用户当前打开的招聘官网页面上识别字段，展示建议答案，允许用户修改部分词语，并单击填入。

## 2. 产品目标

- 扫描当前页面表单字段。
- 以 DOM 字段识别为主，OCR/截图理解为辅。
- 将字段匹配到个人经历库或岗位适配材料。
- 展示置信度、建议答案和引用来源。
- 支持用户局部编辑并单击填入。
- 对低置信度字段要求用户确认。

## 3. 插件页面形态

MVP 推荐 Chrome Side Panel，宽度 360-420px。若 Side Panel 不可用，降级为 popup + 页面浮层。

插件界面分为：

1. 顶部状态区
2. 页面扫描区
3. 字段列表区
4. 答案编辑区
5. 填入操作区

## 4. 页面布局

### 4.1 顶部状态区

展示：

- Beyond CV 标识
- 当前网站域名
- 插件登录状态
- 当前岗位项目选择器
- 扫描/重新扫描按钮

### 4.2 字段列表区

字段按页面顺序展示。每个字段卡片包含：

- 字段原始 label
- 系统识别类型
- 置信度
- 当前状态：未处理、已建议、已填入、需确认、失败
- 快捷按钮：查看、填入、复制

### 4.3 答案编辑区

用户点击某个字段后，展示：

- 字段问题原文
- 建议答案
- 引用资料
- 字数统计
- 语气/长度调节
- 敏感信息提示
- 单击填入按钮

## 5. 字段识别规则

### 5.1 DOM 优先

插件应读取：

- input、textarea、select
- label
- placeholder
- aria-label
- name、id
- 附近文本
- 必填标记
- 字数限制
- 下拉选项

### 5.2 OCR 辅助

以下情况进入 OCR/截图辅助：

- 字段 label 无法从 DOM 获取。
- 官网使用图片化或高度定制组件。
- 页面使用 iframe 且无法直接读取。
- 字段附近文本被复杂布局分离。

OCR 辅助结果必须标记为“视觉识别”，并默认较低置信度。

## 6. 字段类型

| 字段类型 | 示例 | 数据来源 |
|---------|------|---------|
| 基础信息 | 姓名、电话、邮箱、地址 | 个人经历库 |
| 教育信息 | 学校、专业、GPA、毕业时间 | 教育经历 |
| 实习经历 | 公司、职位、职责描述 | 实习经历 |
| 家庭信息 | 父母职业、工作单位 | 家庭信息，敏感 |
| Consent | 是否同意条款 | 用户确认，不自动勾选敏感协议 |
| Cover Letter | Why apply / Motivation | 岗位适配材料 |
| Behavior Question | Leadership、Teamwork 等 | 开放题素材 + 岗位适配 |
| 上传文件 | CV、Transcript | MVP 仅提示，不自动上传 |

## 7. 置信度规则

| 置信度 | 范围 | 行为 |
|-------|------|------|
| 高 | ≥ 85% | 可显示一键填入 |
| 中 | 60%-84% | 显示建议，但要求用户查看后填入 |
| 低 | < 60% | 不允许直接填入，必须确认字段含义 |

置信度来源：

- label 与资料库字段匹配度
- 字段类型
- 页面上下文
- 是否有字数限制
- 是否含敏感字段
- 是否来自 OCR

## 8. 交互逻辑

### 8.1 页面扫描

1. 用户打开招聘官网表单。
2. 点击插件“扫描当前页面”。
3. 插件读取 DOM 字段。
4. 对无法识别部分尝试 OCR 辅助。
5. 插件生成字段列表和置信度。
6. 用户可逐项查看建议答案。

### 8.2 单字段填入

1. 用户点击字段卡片。
2. 插件显示建议答案。
3. 用户可修改部分词语、语气和长度。
4. 用户点击“填入此字段”。
5. 插件写入目标输入框。
6. 字段状态变为“已填入”。

### 8.3 低置信度确认

1. 字段置信度低时显示确认问题。
2. 用户选择字段类型或手动指定资料来源。
3. 系统重新生成答案。
4. 用户确认后才能填入。

### 8.4 批量预填

MVP 可作为 P1 弱入口：

1. 只选择高置信度非敏感字段。
2. 点击“批量预填”前展示字段清单。
3. 用户确认后逐项填入。
4. 敏感字段和开放题不进入默认批量。

## 9. 禁止行为

- 不自动点击最终 Submit / Apply / Send 按钮。
- 不自动同意法律协议或背景调查 consent。
- 不在用户未确认时填入家庭信息、成绩、证件字段。
- 不绕过验证码、登录验证或官网风控。
- 不伪造用户经历。

## 10. 异常与降级

| 异常场景 | 处理方式 |
|---------|---------|
| 页面无法访问 DOM | 提示使用复制粘贴模式 |
| 字段写入失败 | 提供复制按钮，用户手动粘贴 |
| 官网动态刷新 | 提示重新扫描 |
| iframe 无权限 | 标记不支持并提供手动复制 |
| 用户未登录插件 | 显示登录按钮 |
| 当前无岗位项目 | 允许选择或新建岗位项目 |

## 11. 前端设计要求

- 插件侧栏宽度有限，信息必须折叠有序。
- 每个字段状态用图标和颜色辅助，但文字也必须清楚。
- 建议答案编辑器高度可伸缩，长答案不应撑坏布局。
- “填入”按钮要靠近当前答案，避免误填其他字段。
- 敏感字段使用 Shield 图标和明确提示。

## 12. 埋点需求

| 事件名 | 触发时机 | 属性 |
|-------|---------|------|
| extension_open | 打开插件 | domain、login_status |
| extension_scan | 点击扫描 | domain |
| extension_scan_success | 扫描成功 | field_count、recognized_count |
| extension_field_view | 查看字段 | field_type、confidence |
| extension_fill_field | 填入字段 | field_type、confidence、sensitive |
| extension_copy_fallback | 使用复制降级 | reason |
| extension_error | 插件错误 | error_code、domain |

## 13. 验收标准

- 插件可扫描常见招聘官网表单字段。
- 字段列表展示置信度和状态。
- 用户可编辑建议答案并单击填入。
- 低置信度字段必须确认后才能填入。
- 插件不会自动提交申请。
- 写入失败时提供复制降级方案。
