# Beyond CV 页面 PRD：岗位适配 - 材料生成

## 1. 页面概述

| 字段 | 内容 |
|-----|------|
| 页面名称 | 岗位适配工作台 |
| 所属模块 | 岗位适配材料生成 |
| 页面路由 | `/jobs/new`、`/jobs/:id` |
| 页面优先级 | P0 |
| 主要用户 | 需要针对某个岗位生成申请材料的求职者 |
| 前置依赖 | 用户已有基础个人经历库 |
| 后置页面 | 简历生成器、浏览器插件填表 |

岗位适配工作台将岗位 JD 与用户经历库连接起来，生成字段短答、cover letter、behavior question 答案和岗位适配简历建议。页面应强调“材料来自你的真实经历”，并允许用户修改生成内容，而不是让 AI 直接替用户提交。

## 2. 产品目标

- 支持用户粘贴岗位 JD 并解析岗位要求。
- 推荐与 JD 最相关的经历和技能。
- 生成四类材料：字段短答、cover letter、behavior question、岗位适配简历建议。
- 支持字数限制、语气选择、敏感字段参与开关。
- 保存为一个岗位项目，供后续继续编辑和插件调用。

## 3. 页面布局

### 3.1 桌面端

采用两阶段工作台：

阶段一：JD 输入与解析。

- 左侧：JD 输入框。
- 右侧：解析结果，包括公司、岗位、关键词、能力要求。

阶段二：材料生成与编辑。

- 左侧：输出类型和引用经历选择。
- 中间：生成结果编辑器。
- 右侧：岗位摘要、敏感字段开关、插件可用状态。

### 3.2 移动端

- 分步呈现：输入 JD、确认解析、生成材料、编辑保存。
- 生成结果使用全屏编辑器。

## 4. 页面元素

| 区域 | 元素 | 类型 | 说明 |
|-----|------|------|------|
| 顶部 | 岗位名称 | 输入框 | 可由 JD 自动识别 |
| 顶部 | 公司名称 | 输入框 | 可由 JD 自动识别 |
| JD 区 | JD 输入 | 多行文本 | 粘贴完整岗位描述 |
| JD 区 | 解析按钮 | 按钮 | 触发 JD 解析 |
| 解析区 | 岗位关键词 | 标签 | 能力、技能、行业、职责 |
| 解析区 | 岗位要求列表 | 列表 | Required / Preferred |
| 选择区 | 输出类型 | 多选 | 字段短答、CL、BQ、简历建议 |
| 选择区 | 引用经历 | 复选列表 | 推荐相关经历 |
| 设置区 | 字数限制 | 输入框 | 适用于开放题 |
| 设置区 | 语气 | 下拉 | 专业、精炼、热情、保守 |
| 设置区 | 敏感字段开关 | 开关 | 成绩、家庭信息等 |
| 编辑区 | 生成结果 | 编辑器 | 可修改和保存 |

## 5. JD 解析规则

系统应从 JD 中尽量识别：

| 字段 | 说明 |
|-----|------|
| 公司名称 | 从 JD 标题或正文识别 |
| 岗位名称 | 如 Summer Analyst、Legal Intern |
| 地点 | 城市、国家、远程 |
| 岗位职责 | 用于匹配经历 |
| 任职要求 | 技能、学历、语言、行业经验 |
| 关键词 | 金融建模、尽调、数据分析、法律检索等 |
| 申请材料要求 | 是否需要 cover letter、开放题、语言要求 |

低置信度信息必须允许用户编辑。

## 6. 输出类型

### 6.1 字段短答

用于官网结构化字段：

- 教育背景
- 实习经历摘要
- 技能描述
- 申请动机短答
- 家庭信息字段
- 可入职时间

每个短答需显示适用字段、建议字数、引用资料。

### 6.2 Cover Letter

默认结构：

1. 开头：岗位申请意图和公司匹配。
2. 主体一：最相关经历。
3. 主体二：技能和价值。
4. 结尾：期待进一步沟通。

支持长度：150、300、500、800 words / 中文对应字数。

### 6.3 Behavior Question

默认题库：

- Why this firm?
- Why this role?
- Tell me about leadership.
- Tell me about teamwork.
- Tell me about a failure.
- Tell me about a conflict.
- What are your strengths?
- Career goal.

每个答案建议采用 STAR 或动机逻辑，用户可指定字数限制。

### 6.4 岗位适配简历建议

输出内容：

- 推荐放入简历的 2-3 段经历。
- 每段经历的推荐排序。
- 推荐 bullet wording。
- 建议隐藏或弱化的内容。
- 和 JD 关键词的匹配解释。

## 7. 交互逻辑

### 7.1 新建岗位项目

1. 用户点击“新建岗位适配”。
2. 粘贴 JD。
3. 点击解析。
4. 系统显示岗位摘要和关键词。
5. 用户确认或修改。
6. 系统推荐相关经历。
7. 用户选择输出类型并生成。

### 7.2 生成材料

1. 用户选择输出类型。
2. 设置字数、语气、敏感字段开关。
3. 点击生成。
4. 系统生成结果并展示引用了哪些经历。
5. 用户编辑并保存。
6. 保存后的材料可被插件调用。

### 7.3 敏感字段参与

1. 默认不使用家庭信息、成绩、证件类字段。
2. 用户打开开关后，系统提示“该内容可能被用于生成申请材料”。
3. 生成结果中若包含敏感信息，应在段落旁显示标记。

## 8. 状态设计

| 状态 | 页面表现 |
|-----|---------|
| 未输入 JD | 显示 JD 输入引导 |
| JD 解析中 | 显示进度和正在识别的项目 |
| JD 信息不足 | 提示补充岗位名称、公司或职责 |
| 经历匹配不足 | 提示去经历库补充相关经历 |
| 生成中 | 编辑器显示骨架，不阻塞查看解析结果 |
| 已生成未保存 | 顶部显示未保存提示 |
| 生成失败 | 保留设置和 JD，允许重试 |

## 9. 前端设计要求

- 生成结果必须是编辑器，不是只读文本。
- 每段生成内容旁边应能查看“引用资料”。
- 敏感字段开关需要清晰，不要藏在高级设置里。
- 输出类型可用 Tab 或侧边列表切换。
- 页面信息较多，必须保持强分区和清晰层级。

## 10. 埋点需求

| 事件名 | 触发时机 | 属性 |
|-------|---------|------|
| job_create | 新建岗位项目 | source |
| job_parse_jd | 点击解析 JD | jd_length |
| job_parse_success | 解析成功 | keyword_count |
| job_generate | 生成材料 | output_type、sensitive_enabled |
| job_save_material | 保存材料 | output_type、word_count |
| job_open_in_resume | 打开简历建议 | job_id |

## 11. 验收标准

- 用户可粘贴 JD 并得到可编辑解析结果。
- 系统可生成四类 P0 材料。
- 生成结果可编辑、保存、再次打开。
- 用户能看到生成内容引用了哪些经历。
- 敏感字段默认不参与，开启时有明确提示。
