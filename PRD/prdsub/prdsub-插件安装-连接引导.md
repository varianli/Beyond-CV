# Beyond CV 页面 PRD：插件安装 - 连接引导

## 1. 页面概述

| 字段 | 内容 |
|-----|------|
| 页面名称 | 插件安装与连接引导 |
| 所属模块 | 浏览器插件辅助填写 |
| 页面路由 | `/extension` |
| 页面优先级 | P0 |
| 主要用户 | 希望在招聘官网使用单击填入的用户 |
| 前置依赖 | 用户已登录 Web App |
| 后置页面 | 招聘官网插件侧栏 |

该页面负责让用户安装、连接和理解浏览器插件的边界。它不是应用商店介绍页，而是一个操作引导页：用户应该知道插件能做什么、不能做什么、如何确认连接成功，以及如何在招聘官网使用。

## 2. 产品目标

- 引导用户安装 Chrome 插件。
- 完成 Web App 与插件的账号连接。
- 展示插件当前状态。
- 明确说明插件不会自动提交申请或绕过官网限制。
- 提供测试页面或模拟字段，让用户理解一键填入。

## 3. 页面布局

- 顶部：插件状态卡。
- 中部：三步引导。
- 右侧或下方：使用边界说明。
- 底部：测试插件区域。

三步引导：

1. 安装插件
2. 登录并连接账号
3. 打开招聘官网并扫描字段

## 4. 页面元素

| 区域 | 元素 | 类型 | 说明 |
|-----|------|------|------|
| 状态卡 | 插件状态 | 状态标签 | 未安装、已安装未连接、已连接 |
| 状态卡 | 最近连接时间 | 文本 | 已连接时展示 |
| 引导步骤 | 安装按钮 | 按钮 | 跳转 Chrome Web Store 或本地安装说明 |
| 引导步骤 | 连接按钮 | 按钮 | 触发插件登录/授权 |
| 引导步骤 | 使用说明 | 步骤列表 | 打开官网、扫描、编辑、填入 |
| 边界说明 | 不自动提交 | 信息提示 | 强调用户自行提交 |
| 测试区域 | 模拟字段 | 输入框 | 姓名、学校、cover letter |
| 测试区域 | 触发测试 | 按钮 | 检查插件是否可识别 |

## 5. 交互逻辑

### 5.1 未安装状态

1. 页面检测不到插件连接。
2. 显示“安装 Chrome 插件”按钮。
3. 用户点击后进入安装说明。
4. 安装后返回页面，状态更新。

### 5.2 已安装未连接

1. 页面检测插件存在但未登录。
2. 显示“连接账号”按钮。
3. 用户点击后唤起插件登录。
4. 登录成功后 Web App 显示已连接。

### 5.3 已连接状态

1. 页面展示连接成功、浏览器名称、最近使用时间。
2. 提供“打开测试表单”。
3. 用户可测试字段扫描和填入。

## 6. 边界说明文案

页面必须明确展示：

- 插件只在你主动点击扫描时分析当前页面。
- 插件会给出建议答案，填入前你可以修改。
- 插件不会自动点击最终提交按钮。
- 插件不会自动同意法律协议或 consent。
- 低置信度字段和敏感字段需要你确认。

## 7. 状态设计

| 状态 | 页面表现 |
|-----|---------|
| 未安装 | 主按钮为“安装插件” |
| 已安装未连接 | 主按钮为“连接账号” |
| 已连接 | 主按钮为“打开测试表单” |
| 检测中 | 状态卡显示 loading |
| 检测失败 | 显示手动刷新状态按钮 |
| 浏览器不支持 | 提示 Chrome 最新版优先 |

## 8. 前端设计要求

- 步骤引导要紧凑清晰，避免长篇教程。
- 插件状态要非常明显，让用户知道下一步。
- 测试区域使用真实表单样式，帮助用户建立使用预期。
- 边界说明使用短句和图标，不使用法务式长段落。

## 9. 验收标准

- 用户能从页面理解如何安装和连接插件。
- 页面能展示插件连接状态。
- 页面明确说明不自动提交申请。
- 用户可进入测试区域验证基本填入能力。
- 浏览器不支持时有清晰替代说明。
