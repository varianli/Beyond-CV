# Beyond CV 页面 PRD：个人经历库 - 资料管理

## 1. 页面概述

| 字段 | 内容 |
|-----|------|
| 页面名称 | 个人经历库 |
| 所属模块 | 个人经历库 |
| 页面路由 | `/profile` |
| 页面优先级 | P0 |
| 主要用户 | 已完成或正在完善资料的求职者 |
| 前置依赖 | 用户已登录 |
| 后置页面 | 简历生成器、岗位适配、插件填表 |

个人经历库是 Beyond CV 的数据底座。它不是普通简历编辑器，而是保存“简历内外所有求职相关事实”的结构化资料库。页面应支持快速浏览、编辑、补充、隐藏敏感字段，并让用户清楚每条资料可用于哪些场景。

## 2. 产品目标

- 让用户集中管理教育、实习、校园、技能、家庭信息、开放题素材。
- 支持每类经历的新增、编辑、删除、复制、排序和敏感控制。
- 支持中英文内容并存。
- 让用户知道资料是否足够用于简历、岗位适配和官网填表。

## 3. 页面布局

### 3.1 桌面端

- 左侧：资料分类导航。
- 中间：所选分类列表。
- 右侧：详情编辑面板或资料质量建议。

分类导航包含：

1. 基础信息
2. 教育经历
3. 实习经历
4. 校园与领导力
5. 技能与证书
6. 家庭信息
7. 开放题素材
8. 敏感字段总览

### 3.2 移动端

- 分类导航改为顶部横向 Tab。
- 列表和详情采用上下钻取。
- 编辑表单全屏打开，底部固定保存按钮。

## 4. 页面元素

| 区域 | 元素 | 类型 | 说明 |
|-----|------|------|------|
| 顶部 | 页面标题 | 文本 | “个人经历库” |
| 顶部 | 资料覆盖率 | 进度/标签 | 用于简历、官网填表、开放题的覆盖度 |
| 顶部 | 新增资料 | 按钮 | 根据当前分类新增 |
| 分类导航 | 分类项 | 导航 | 显示数量和缺失状态 |
| 列表区 | 经历卡片 | 列表项 | 标题、时间、摘要、标签 |
| 列表区 | 排序控件 | 拖拽/按钮 | 控制简历默认排序 |
| 详情区 | 字段表单 | 表单 | 编辑结构化字段 |
| 详情区 | 使用场景 | 标签 | 简历、短答、cover letter、官网字段 |
| 详情区 | 敏感开关 | 开关 | 控制是否参与生成 |

## 5. 分类详情

### 5.1 基础信息

| 字段 | 类型 | 必填 | 用途 |
|-----|------|------|------|
| 中文姓名 | 输入框 | 否 | 中文简历、官网字段 |
| 英文姓名 | 输入框 | 否 | 英文简历 |
| 手机号 | 输入框 | 是 | 官网字段 |
| 邮箱 | 输入框 | 是 | 官网字段 |
| 当前城市 | 输入框 | 否 | 官网字段 |
| 地址 | 输入框 | 否 | 英文简历可选 |

### 5.2 教育经历卡片

卡片展示：

- 学校名称
- 学位与专业
- 时间范围
- GPA/荣誉标签
- 是否含敏感字段
- 是否已用于简历

支持操作：

- 编辑
- 复制为英文版本
- 上移/下移
- 隐藏成绩
- 删除

### 5.3 实习经历卡片

卡片展示：

- 公司名称、部门、职位
- 起止时间、地点
- 3 条以内核心 bullet 预览
- 关联项目数量
- 岗位适配使用次数

支持操作：

- 编辑事实信息
- 编辑 bullet
- AI 改写为英文/中文
- 标记为重点经历
- 从简历候选中隐藏

### 5.4 开放题素材

素材按问题类型组织：

| 类型 | 说明 |
|-----|------|
| Why this firm | 公司动机 |
| Why this role | 岗位动机 |
| Leadership | 领导力 |
| Teamwork | 团队合作 |
| Failure | 失败复盘 |
| Conflict | 冲突处理 |
| Strength/Weakness | 优势与不足 |
| Career goal | 职业规划 |

每条素材包含：标题、STAR 结构、可引用经历、适用岗位、敏感等级。

## 6. 交互逻辑

### 6.1 新增资料

1. 用户在分类下点击“新增”。
2. 右侧打开空白表单。
3. 用户填写字段。
4. 前端实时校验必填项。
5. 点击保存后写入资料库。
6. 列表刷新，资料覆盖率更新。

### 6.2 编辑资料

1. 点击卡片进入详情。
2. 修改字段后显示“未保存”状态。
3. 点击保存后更新。
4. 若该资料已用于某个简历版本，提示“不会自动覆盖已保存版本，可在简历页同步更新”。

### 6.3 删除资料

1. 点击删除。
2. 弹窗说明影响：可能影响简历和岗位材料。
3. 用户确认后软删除。
4. 30 天内可从回收站恢复，MVP 可先保留删除确认但不做回收站。

### 6.4 敏感字段控制

1. 用户打开含敏感信息的资料。
2. 字段旁显示敏感标签。
3. 用户可关闭“参与 AI 生成”或“参与插件填表”。
4. 关闭后，生成材料时不使用该字段。

## 7. 状态设计

| 状态 | 页面表现 |
|-----|---------|
| 分类为空 | 显示空状态、示例和新增按钮 |
| 编辑未保存 | 顶部/底部显示未保存提示 |
| 保存中 | 保存按钮 loading，表单可保持显示 |
| 保存失败 | 错误条 + 重试，不丢失本地修改 |
| 字段敏感 | 字段旁显示 Shield 图标和说明 |
| 资料冲突 | 显示冲突提示，例如时间重叠 |

## 8. 前端设计要求

- 资料库应像专业数据库工具，而不是简历模板编辑器。
- 列表卡片信息密度要高，便于扫描和比较。
- 敏感字段视觉提示要明显但不过度惊吓。
- 编辑区建议固定底部保存栏，避免长表单找不到保存按钮。
- 删除、隐藏、参与生成是不同概念，文案必须区分。

## 9. 埋点需求

| 事件名 | 触发时机 | 属性 |
|-------|---------|------|
| profile_view | 进入经历库 | completion |
| profile_add_item | 新增资料 | category |
| profile_save_item | 保存资料 | category、has_sensitive |
| profile_delete_item | 删除资料 | category |
| profile_toggle_sensitive | 切换敏感开关 | field、enabled |
| profile_ai_rewrite | 点击 AI 改写 | category、language |

## 10. 验收标准

- 用户可管理所有 P0 资料分类。
- 每条资料可新增、编辑、删除。
- 敏感字段可单独控制是否参与生成和填表。
- 修改资料后资料覆盖率同步变化。
- 保存失败不会丢失用户已输入内容。
