# Beyond CV 页面 PRD：首页工作台 - 申请总览

## 1. 页面概述

| 字段 | 内容 |
|-----|------|
| 页面名称 | 首页工作台 |
| 所属模块 | Web App 总控台 |
| 页面路由 | `/dashboard` |
| 页面优先级 | P0 |
| 主要用户 | 已登录求职者 |
| 前置依赖 | 用户已登录 |
| 后置页面 | 个人经历库、简历生成器、岗位适配、插件安装引导 |

首页工作台是用户登录后的操作入口，不做营销首页。它应该像一个高效率求职驾驶舱，帮助用户知道“资料是否完整、下一步该做什么、最近在申请什么、还能节省多少重复填写时间”。页面需要支持新手和回访两种状态。

## 2. 产品目标

- 汇总用户个人资料完整度、简历状态、岗位适配状态和插件状态。
- 提供 3 个核心快捷入口：完善资料、生成简历、适配岗位。
- 给首次用户明确下一步，不让用户进入空白系统后迷路。
- 给回访用户展示最近岗位、最近生成材料、插件填充记录。

## 3. 用户故事

| 编号 | 用户故事 | 优先级 |
|-----|---------|--------|
| US-DASH-01 | 作为新用户，我希望知道还需要补哪些资料才能开始生成简历 | P0 |
| US-DASH-02 | 作为回访用户，我希望快速进入最近编辑的岗位材料 | P0 |
| US-DASH-03 | 作为用户，我希望确认浏览器插件是否已连接 | P0 |
| US-DASH-04 | 作为用户，我希望看到自己申请填写效率的提升 | P1 |

## 4. 页面布局

### 4.1 桌面端布局

采用左侧导航 + 主内容区：

- 左侧导航：工作台、经历库、简历、岗位适配、插件、设置。
- 主内容顶部：问候语、资料完成度、插件状态。
- 主内容中部：核心任务卡片，三列布局。
- 主内容下部：最近岗位材料、最近简历版本、待补资料。

避免多层卡片嵌套。工作台卡片只用于独立任务入口，每张卡不超过一个主要按钮。

### 4.2 移动端布局

- 顶部显示当前页面标题和用户菜单。
- 核心任务入口纵向排列。
- 最近记录以列表形式展示。
- 左侧导航收起为底部 Tab 或抽屉。

## 5. 页面元素

| 区域 | 元素 | 类型 | 说明 |
|-----|------|------|------|
| 顶部 | 问候语 | 文本 | 显示用户姓名或邮箱 |
| 顶部 | 资料完整度 | 进度条 | 教育、实习、技能、开放题素材等完成度 |
| 顶部 | 插件连接状态 | 状态标签/按钮 | 未安装、已安装未登录、已连接 |
| 快捷入口 | 完善资料 | 操作卡 | 进入首次建档或经历库 |
| 快捷入口 | 生成简历 | 操作卡 | 进入简历生成器 |
| 快捷入口 | 适配岗位 | 操作卡 | 进入 JD 输入页 |
| 内容区 | 最近岗位材料 | 列表 | 最近 5 个岗位适配记录 |
| 内容区 | 最近简历版本 | 列表 | 最近 3 个简历版本 |
| 内容区 | 待补资料 | Checklist | 缺少家庭信息、开放题素材等 |

## 6. 信息架构

### 6.1 资料完整度维度

| 维度 | 计算方式 | MVP 权重 |
|-----|---------|---------|
| 基础信息 | 姓名、联系方式、邮箱 | 10% |
| 教育经历 | 至少一段教育经历 | 20% |
| 实习经历 | 至少一段实习或项目经历 | 25% |
| 校园/领导力经历 | 至少一段 | 15% |
| 技能证书 | 至少一组技能 | 10% |
| 开放题素材 | 至少 3 个常见问题素材 | 15% |
| 家庭信息 | 可选，若填写则提高官网填表能力 | 5% |

### 6.2 最近记录字段

| 字段 | 说明 |
|-----|------|
| 岗位名称 | 从 JD 解析或用户手动输入 |
| 公司名称 | 从 JD 解析或用户手动输入 |
| 最近编辑时间 | 用于排序 |
| 已生成内容 | 短答、cover letter、behavior question、适配简历 |
| 状态 | 草稿、已生成、已用于填表 |

## 7. 交互逻辑

### 7.1 新用户进入

1. 用户首次登录进入 `/dashboard`。
2. 系统检测资料完成度低于 30%。
3. 页面展示“开始建立个人经历库”的主任务。
4. 用户点击后进入 `/onboarding`。
5. “生成简历”和“适配岗位”按钮可见但弱化，点击时提示先补充资料。

### 7.2 回访用户进入

1. 用户登录进入工作台。
2. 系统加载资料完整度、最近岗位和简历版本。
3. 用户可点击最近岗位继续编辑。
4. 用户可直接新建岗位适配或进入简历生成器。

### 7.3 插件状态

1. 若未检测到插件连接，显示“安装插件”入口。
2. 若插件已安装但未登录，显示“连接插件”。
3. 若已连接，显示最近一次使用时间。

## 8. 状态设计

| 状态 | 页面表现 |
|-----|---------|
| 新用户空状态 | 显示三步任务：建档、生成简历、安装插件 |
| 资料不足 | 生成类入口提示缺少资料，不直接报错 |
| 加载中 | 展示骨架屏，避免页面跳动 |
| 最近记录为空 | 显示创建入口，不展示空表格 |
| 插件未安装 | 显示安装引导和 Chrome 支持说明 |
| 接口失败 | 保留导航，主区域显示重试按钮 |

## 9. 前端设计要求

- 工作台整体风格应专业、清晰、偏工具型，不做夸张视觉。
- 主 CTA 只保留一个：新用户是“开始建立经历库”，老用户是“新建岗位适配”。
- 资料完整度不能让用户感到被评分，应表达为“可用于自动填写的资料覆盖率”。
- 列表信息密度适中，避免大面积空白。
- 所有入口都要有明确图标，可使用 lucide icons：UserRound、FileText、Briefcase、Shield、Puzzle。

## 10. 埋点需求

| 事件名 | 触发时机 | 属性 |
|-------|---------|------|
| dashboard_view | 进入工作台 | profile_completion、plugin_status |
| dashboard_click_onboarding | 点击完善资料 | completion |
| dashboard_click_resume | 点击生成简历 | resume_count |
| dashboard_click_job | 点击适配岗位 | job_count |
| dashboard_click_plugin | 点击插件入口 | plugin_status |

## 11. 验收标准

- 新用户可从工作台明确进入建档流程。
- 老用户可看到最近岗位和简历版本。
- 插件状态展示准确，且有下一步操作。
- 页面在无数据时不出现空白表格。
- 移动端核心入口不折叠到不可发现的位置。
